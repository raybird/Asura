## 實作方向草案

以 Go HTTP 與內嵌靜態頁面提供單一入口，經 Unix Socket 呼叫既有 Daemon。登入留在 Web；專案政策取自 Daemon，不讓瀏覽器或另一份可擴權設定成為授權來源。需要列出可選專案或分頁結果時，只擴充必要 IPC。

使用服務端工作階段、HttpOnly cookie 與跨站請求防護；密鑰來源採服務端檔案或環境設定，不放 URL。監聽位址、session 失效政策與 HTTPS／代理設定須在 Phase 1 落成可審查設定契約：預設 loopback，私人介面由使用者明確指定；不能無條件相信任意代理標頭。這些是待完整劇本核准後細化的實作方向，並非已驗證部署。

長輸出須有明確頁界與排序，完成結果可完整重組；中斷結果只能宣稱已持久化部分。對應故障證據見 [拆解](implementation-plan-decomposition.md)。

# Issue 4：Phase 2A 單一 Web 遠端入口

建立日期：2026-09-13。追蹤：[GitHub Issue #4](https://github.com/raybird/Asura/issues/4)。承接 [Phase 1.5](../issue-2/README.md) 與 [階段規劃](../../plans/post-core-roadmap.md)。

## 概述

本人在私人網路透過 Web 提交自然語言任務、取得 Task ID、查詢與取消，全部共用 Daemon 的授權、容量與任務資料。臨時對外 tunnel 由使用者另行操作外部工具，本期不整合 tunnel、Telegram、Cron、多帳號或新執行池。

## 風險與首要驗證

- **最大風險**：未登入或越權請求觸發本機副作用、取消任務或取得輸出。
- **風險等級與理由**：High，涉及遠端授權與本機執行；Large 另由 Web、CLI、Daemon、儲存跨模組整合判定。
- **首要驗證**：規格核准後，先建立 HTTP／服務端授權拒絕的外迴圈紅燈，再以最小登入及授權實作取得允許／拒絕對照證據；先於一般頁面功能。
- **選擇理由**：直接檢查拒絕請求到執行／讀取邊界，最能降低最大風險；不以畫面隱藏按鈕代表授權。
- **完成證據**：正向對照確實啟動一次受控後端；拒絕對照零啟動、零可執行任務、零取消副作用、回應不含受保護內容。工作目錄清單不宣稱為作業系統沙箱。

## Gherkin 驗收劇本

2026-09-13：下列為依逐題決策整理的完整草案；WEB-010 是登入邊界的具體補充，亦待整體核准。未進入 production code 實作。

```gherkin
Feature: 本人在私人網路安全操作共同任務中樞

  @WEB-001
  Scenario: 密鑰登入與未登入拒絕
    Given 服務端設定單一存取密鑰
    When 本人輸入正確密鑰
    Then 建立可操作 Web 的登入工作階段
    And 未登入或密鑰錯誤的請求不能提交、查詢結果或取消任務
    And 拒絕請求不建立可執行任務、不啟動後端且不洩漏輸出

  @WEB-002
  Scenario: 專案授權涵蓋提交查詢與取消
    Given 已登入且 Daemon 只允許專案 A
    When 使用者操作 A 或清單外專案 B 的任務
    Then A 可提交任務並可查詢及取消由 Web 或 CLI 提交的任務
    And B 的提交、查詢與取消均遭拒絕且沒有副作用或輸出洩漏
    And 瀏覽器不能修改或擴大服務端允許清單

  @WEB-003
  Scenario: 接受任務與共同容量
    Given 已登入且專案獲授權
    When Web 提交自然語言任務
    Then 容量與持久化接受成功後才回傳可追蹤的 Task ID
    And 任務共用 CLI 的中樞容量且不被當作 shell 命令
    And 滿載或中樞不可用時明確回報未接受且不另起執行器

  @WEB-004
  Scenario: 回應遺失重送不重複執行
    Given 中樞已接受任務但瀏覽器未收到接受回應
    When 瀏覽器以同一提交識別與相同內容重送或於重開後恢復查詢
    Then 可追蹤原任務且後端執行次數仍為一次
    And 任務與去重紀錄在服務重啟後仍可查得且本期不自動清除

  @WEB-005
  Scenario: 重送衝突與取消後重新執行
    Given 一個提交識別已有對應任務
    When 同識別換用不同專案或內容或重送已取消任務
    Then 拒絕該提交且不再啟動後端
    And 使用者明確重新執行時以新識別建立新任務

  @WEB-006
  Scenario: 關閉頁面後恢復狀態與結果
    Given 已接受任務且使用者保存其追蹤識別
    When 關閉頁面後重新開啟並登入查詢
    Then 可查得同一任務的狀態與已保存結果
    And 開啟頁面定期更新狀態且查詢不重跑或取消任務

  @WEB-007
  Scenario: 長輸出以純文字分頁交付
    Given 已登入且授權任務的保存結果含多頁文字及 HTML 樣式字串
    When 使用者讀取所有結果頁
    Then 可依序還原完整保存文字而無遺漏或重複
    And 內容不作為 HTML 或腳本執行
    And 本期不自動遮蔽輸出中的敏感資訊且未登入不得讀取任一頁

  @WEB-008
  Scenario: 共同取消如實回報
    Given 授權任務 A 執行中且存在不相關任務 B
    When 本人透過 Web 取消 A
    Then 透過共同中樞取消且確認回收後才回報完成
    And 無法確認回收時顯示錯誤並保留追蹤資訊
    And B 不受影響

  @WEB-009
  Scenario: 失敗與服務重啟保留真實結果
    Given 任務可能已有持久化輸出
    When 後端失敗或中樞中斷後重啟
    Then Web 可查得失敗或中斷狀態與已保存輸出
    And 不將未知結果標成成功也不自動重跑副作用

  @WEB-010
  Scenario: 工作階段與跨站請求維持登入邊界
    Given 使用者已登入或曾持有已失效的工作階段
    When 使用者登出或外站試圖借用瀏覽器登入狀態提交與取消
    Then 登出後的工作階段與跨站變更請求被拒絕且無任務副作用
    And 密鑰不出現在 URL、一般日誌或任務結果中
```

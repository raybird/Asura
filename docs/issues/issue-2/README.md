## 現況與最小邊界

2026-09-12 依 main `1cd0301` 查核：

- [CLI](../../../cmd/asura/run.go) 的 run 以 `sh -c` 執行輸入，提供 run／status／cancel，尚未提供正式 daemon 子命令。
- [Engine](../../../internal/engine/engine.go) 預設 runner 回報 `no default runner configured`；[OpenCode 模組](../../../internal/backend/opencode/parser.go) 已有解析及程序管理能力，但不能據此認定自然語言提交已串通。
- [Daemon](../../../internal/daemon/daemon.go) 有 Socket、WorkerPool 與同步結果回應；CLI run 尚未經此 WorkerPool。
- 取消、程序身分與收尾已有測試及修復；新增入口應共用這些責任，不各自複製。

## 涉及檔案

預期改動邊界為 `cmd/asura`、`internal/daemon`、`internal/engine`、`internal/backend/opencode`、必要的 `internal/storage` 與對應測試。沒有 migration 必要時不修改 schema；不預先新增通用插件框架或多後端選擇系統。遠端入口、Cron、記憶、三面管線不在此交付。

## 風險與首要驗證

- **最大風險**：自然語言是否真的交給受核准權限約束的 OpenCode，以及多個入口是否共用執行容量；錯誤接線可能把 prompt 當 shell 命令或繞過限制。
- **風險等級與理由**：High，涉及本機執行副作用及跨程序資源所有權。規模 Large 是因為跨 CLI、Daemon、Engine、後端與持久化整合。
- **首要驗證**：先確認 CLI 相容性、Daemon 模式與權限決策，對固定版本後端執行允許／拒絕的最小契約探測；再做一條真實提交路徑。
- **選擇理由**：後端與權限未知先用契約證據消除；其後的最大未知才是跨模組接線，因此使用最窄端到端路徑。
- **完成證據**：固定版本、命令、樣本與退出碼；拒絕請求零後端啟動；正式 CLI 取得 Task ID、查得結果，並能透過共同中樞取消及遵守容量上限。

    Then 確認回收成功才宣告完成
    And 無法確認身分或回收結果時回報錯誤並保留追蹤資訊

  @INT-006
  Scenario: 後端失敗與服務重啟保留追蹤資訊
    Given 任務已有可追蹤識別且可能產生部分輸出
    When 後端失敗或執行服務中斷後重新啟動
    Then 可查得明確失敗或中斷結果及已持久化的輸出
    And 不將結果未知標成成功或自動重跑副作用

## 2026-09-12 核准決策補充

1. 保留 `asura run` 的 shell 語意，新增 `asura ask` 提交自然語言 AI 任務；來源：使用者回覆「保留」。INT-001 的 AI 提交指令據此具體化為 ask，不把原 run 改成 AI 呼叫。
2. Daemon 手動啟動，不可用時回報錯誤，不自動啟動或回退成獨立執行；來源：使用者回覆「依照建議」。
3. 專案允許清單由 Daemon 管理，ask 只能選擇已核准專案，不得自行擴大授權；來源：使用者回覆「依照建議」。此為入口授權，不代表作業系統沙箱隔離。
4. 確認有執行或排隊容量且持久化成功後，才回傳已接受與 Task ID。客戶端斷線不取消任務，只有明確 cancel 才要求取消。同一請求識別可查回原任務，避免接受回應遺失後重送造成重複執行；來源：使用者回覆「採用」。
5. 確認資源回收後才回報取消完成；無法確認時回報錯誤並保留追蹤資訊。重啟保留已完成結果，中斷任務明確標記，不自動重跑副作用；來源：使用者回覆「沿用」。
6. 先固定 OpenCode `1.18.23`，串接前重新驗證啟動參數、事件格式與取消行為；若版本不可用或契約有變，再另行決定升級；來源：使用者回覆「依照建議」。此決策不是已完成重新探測的證據。

INT-004 依第 4 項增加下列已核准的失敗路徑，作為原劇本的補充，保留初稿時序：

```gherkin
  @INT-004-REDELIVERY
  Scenario: 接受回應遺失後重送不重複執行
    Given 任務已確認容量且持久化接受但客戶端未收到回應
    When 客戶端以同一請求識別重送相同任務
    Then 回傳原任務的 Task ID
    And 不再次執行任務
```

2026-09-12 第七題補充核准：使用者對「允許後端在核准專案內自動修改檔案、執行建置與測試，但刪除重要資料、部署、推送及對外傳送資訊仍須另行確認」回覆「依照建議」。此授權不擴及任意命令或上述需確認的操作；實際後端的權限能力必須先驗證，不能只以 prompt 宣告限制已生效。

    But 刪除重要資料、部署、推送及對外傳送資訊必須另行取得確認

## 雙迴圈驗證計畫

| Scenario | 外迴圈 | 內迴圈 | 目標紅燈 |
|---|---|---|---|
| INT-001 | 正式 CLI → Daemon → 固定版本 OpenCode → status | adapter 事件與結果轉換 | AI 提交未接後端或結果不可重查 |

| INT-005 | 取消 A，檢查其資源與不相關 B；注入身分未知 | 回收結果與錯誤傳遞 | 假成功、遺失回收資訊或誤傷 B |
| INT-006 | 真實失敗及中止／重啟服務，查詢已保存任務 | 失敗分類與持久化終態 | 部分輸出遺失、未知被標成功或重跑 |
| INT-007 | 在隔離測試專案驗證允許的修改／建置／測試，並以受控目標確認需核准操作未獲確認時零執行 | 操作權限與確認結果傳遞 | 未獲確認即執行受限制操作；由 B-00 驗證契約、B-01 接線、B-05 回歸 |

以標註 INT 編號的 Go 整合測試替代獨立 BDD runner，內迴圈使用 Go 單元測試。實作時保存外迴圈紅燈、內迴圈紅燈、最小實作全綠與重構後全綠的命令／退出碼／輸出；未執行的測試不得填 PASS。既有 `go test -count=1 -race ./...` 作為回歸基線，真實後端測試另記錄版本與獨立命令。Socket 測試若遭環境阻擋，取得允許的執行環境後驗證，不能略過再宣稱全綠。

## I-01 [P2] 保留取消握手失敗後重試資源回收的能力

位置：`cmd/asura/cancel.go:59-66`，與前面的 `CancelTask` 呼叫相互影響。

取消端在取得啟動鎖之前已將資料庫狀態寫成 cancelled。新增的開鎖／加鎖失敗返回會直接跳過 PGID 強殺，留下仍在執行的程序；即使使用者排除鎖錯誤再試，下一次 `CancelTask` 也會因狀態已是 cancelled 而返回 `task is not running`，永遠到不了資源回收。狀態被標成取消，但原工作仍可繼續產生副作用。

應保留可重試的取消收尾狀態，或讓已請求取消但尚未確認回收的任務再次進行握手／回收；不要把 cancelled 視為已完成資源回收的充分證據。

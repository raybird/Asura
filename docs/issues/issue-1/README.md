    Then 已完成任務的結果仍可查得

  Scenario: 空輸出與結構化錯誤不被當成成功

    Then 使用者取得明確結果或失敗原因
    And 補總結次數不超過核准上限
    And 收尾不重做原任務的副作用

## 風險與首要驗證

- **最大風險**：入口可驅動本機寫入與命令，但授權邊界未定義；最嚴重後果是未授權副作用。最大技術未知是後端的權限、事件、取消及會話控制能力。
- **風險等級與理由**：High，涉及權限與副作用，且核心外部契約未確認。Large 則源於跨模組、持久化與入口整合的範圍，並非由風險推導。
- **首要驗證**：先核准 D-01 權限矩陣，在獨立測試目錄以允許／拒絕成對案例探測單一後端，再探測 D-05、D-08。
- **選擇理由**：契約探測直接確認能否限制後端執行、辨識結果與回收資源；完整端到端串接無法替代此證據。
- **完成證據**：記錄版本、命令與輸出；允許案例確有執行，拒絕案例無後端啟動及寫入，取消資源可回收且既有工作不受影響。Context 能力若不足，明確縮減範圍後取得核准。

```gherkin
Feature: 可控且可追蹤的本機任務執行

  @SCN-001
  Scenario: 授權使用者取得單次任務結果
    Given 使用者可操作指定專案且執行後端可用
    When 使用者透過本機 CLI 提交一項無外部副作用的任務
    Then 使用者取得可追蹤的任務識別與完成結果
    And 可再次查得相同任務的結果

  @SCN-002
  Scenario: 拒絕超出授權範圍的執行
    Given 使用者沒有指定專案的執行權限
    When 使用者提交該專案的任務
    Then 使用者收到拒絕原因
    And 沒有啟動執行後端或造成檔案變更

  @SCN-003
  Scenario: 競爭啟動仍只執行一次已接受任務
    Given 守護程序尚未就緒
    When 兩個本機請求與守護程序同時啟動
    Then 每個已接受的任務各執行一次
    And 未接受的請求得到明確結果
    And 執行數量不超過核准的全域上限

  @SCN-004
  Scenario: 取消任務不影響其他工作
    Given 任務 A 正在執行且另有使用者原有工作 B
    When 使用者取消任務 A
    Then A 在核准的取消期限內停止並呈現取消結果
    And A 擁有的執行資源被回收
    And B 仍可操作

  @SCN-005
  Scenario: SCN-005: 部分執行失敗不自動重做副作用且揭露已知進度
    Given 任務已在工作目錄中產生一項可驗證的副作用（例如已建立暫存檔案或寫入部分輸出）
    When 執行後端遭遇非 0 退出碼或中斷錯誤導致後續步驟無法完成
    Then 該任務之最終狀態標記為 "failed"（而非 completed 或自動重啟為 pending）
    And 系統絕不自動重跑或重試該任務，以杜絕重複副作用
    And 透過 CLI status 查詢該任務時，能正確查得已產生的部分輸出與明確的失敗原因

  @SCN-006
  Scenario: SCN-006: 守護程序重啟保留已完成結果並將中斷任務標記為失敗揭露原因
    Given 系統中存在已成功完成之任務 A (status: completed) 且另一個任務 B 尚在執行中 (status: running)
    When 守護程序意外終止或崩潰後重新啟動並執行恢復程序
    Then 已完成任務 A 的執行結果仍完整保留且可重複查得 (status: completed)
    And 未確認完成之任務 B 絕不呈現為成功，亦不自動從頭重新執行
    And 任務 B 之狀態在重啟恢復後轉移為 "failed"，並明確標註 "task interrupted: system restarted or terminated unexpectedly"

  @SCN-007
  Scenario: SCN-007: 空白輸出或結構化錯誤不被當成成功且明確告知失敗原因
    Given 任務執行後端未產出有效文字（輸出為空字串或純空白）或只回傳未解決之結構化錯誤事件
    When 任務進入結果判定與收尾程序
    Then 該任務之最終狀態嚴格不得標記為 "completed"
    And 該任務之狀態必須明確標記為 "failed"
    And 錯誤訊息明確標註 "execution produced empty output or unresolved error"，供使用者精準追蹤失敗原因
    And 收尾程序絕不重新執行以避免重複副作用
```

## 風險與首要驗證

- **最大風險**：入口可驅動本機寫入與命令，但授權邊界未定義；最嚴重後果是未授權副作用。最大技術未知是後端的權限、事件、取消及會話控制能力。
- **風險等級與理由**：High，涉及權限與副作用，且核心外部契約未確認。Large 則源於跨模組、持久化與入口整合的範圍，並非由風險推導。
- **首要驗證**：先核准 D-01 權限矩陣，在獨立測試目錄以允許／拒絕成對案例探測單一後端，再探測 D-05、D-08。
- **選擇理由**：契約探測直接確認能否限制後端執行、辨識結果與回收資源；完整端到端串接無法替代此證據。
- **完成證據**：記錄版本、命令與輸出；允許案例確有執行，拒絕案例無後端啟動及寫入，取消資源可回收且既有工作不受影響。Context 能力若不足，明確縮減範圍後取得核准。

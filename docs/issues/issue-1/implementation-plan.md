## 設計方案與邊界

建議流程為入口授權 → 接受並記錄任務 → 取得執行容量 → 呼叫單一後端 → 共同收尾 → 保存並回傳結果。先確認各步的失敗契約，再定義函式介面及 schema；2026-09-11 尚無既有可執行流程或可比較的 API 簽名。

首版候選提供本機 CLI 提交、取消與查詢；精確指令語法於 TBD-1 核准時確認。Daemon 不可用時如何回應依 D-02 決定，避免提前將 Standalone 回退實作成定案。

## 測試策略與雙迴圈追蹤

2026-09-11 尚無 Go 模組或 BDD runner。候選方案是以標註 Scenario ID 的 Go 整合測試作為外迴圈，以單元測試驅動內部規則；此為 BDD runner 的替代方式，測試檔案與實際命令在建立測試入口時確定並記錄。

| Scenario | 外迴圈：可觀察驗證 | 內迴圈：最小規則 | 預期紅燈原因 |
|---|---|---|---|
| SCN-001 | CLI 提交並重新查詢同一結果 | 任務狀態轉移與結果保存 | 尚無提交／保存／查詢能力 |
| SCN-002 | 未授權請求不啟動後端且無檔案變更；允許請求可執行 | 權限矩陣判定 | 缺少授權拒絕能力 |
| SCN-003 | 真實多程序競爭啟動與執行計數 | 擁有權取得／釋放及容量計數 | 缺少競爭協調或上限控制 |
| SCN-004 | 取消 A 並確認 B 仍可操作 | 資源歸屬與取消狀態 | 缺少局部回收或取消結果 |
| SCN-005 | 副作用前後注入失敗並獨立計數 | 可重試／結果未知的分類 | 缺少部分執行保護 |
| SCN-006 | 真實終止與重啟後查詢兩種任務 | 中斷狀態恢復 | 缺少持久化或恢復判定 |
| SCN-007 | 錯誤／空輸出仍有明確結果且不重做工作 | 錯誤分類與補總結上限 | 缺少共同收尾 |

每個已核准 Scenario 保存外迴圈紅燈、內迴圈紅燈、最小實作後全綠與重構後全綠的實際命令、退出碼、輸出及原因。不能以測試入口缺失或語法錯誤充當行為紅燈。預期結果來自核准規格、固定案例與獨立副作用計數；後端樣本測試不替代真實後端契約探測。
